# AI Commerce OS 2608·V2 设计系统（Design System）

状态：初稿，待 Founder 确认。

本文件建立 V2 独立的设计语言。**不沿用** V1 的 `frontend/src/styles/theme.css` 及 Design DNA 既有 token 命名
（`--sidebar-text-primary`、`--glass-surface` 等）作为默认继承——V2 视觉如需引用 V1 的具体数值，须在本文件中重新定义并说明理由，不隐式引用旧文件。

## 1. 设计哲学

> AI Commerce OS 不销售软件，销售的是经过 Founder 真实验证的 AI 商业系统。

视觉语言必须服务于这句话，而不是服务于"看起来像一个 SaaS 后台"。八字方针：

**极简 · 高级 · 企业级 · 内容优先 · 大面积留白 · 动画克制 · 层级清晰 · 高品质质感**

借鉴现代 AI 产品与优秀官网的设计理念：极简导航、大面积留白、卡片式布局、沉浸式视觉、平滑过渡、内容优先。

**明确禁止**：传统后台风格、密集菜单、密集表格作为默认呈现、复杂数据墙（大量并列 KPI 卡片堆砌）。

## 2. 品牌标识

| 层级 | 内容 | 使用规则 |
|---|---|---|
| 主品牌 | **SinoFUT** | 系统左上角唯一最高品牌位，任何页面不可替换 |
| 系统名 | AI Commerce OS | 主品牌下方次级文字，字重更轻、字号更小 |
| 版本号 | Version 2608·V2 | 出现在品牌区 hover/展开态，或系统设置页，不作为常驻大字 |
| 次级身份标签 | Founder / Operator / Studio / Growth / Marketplace / Cloud | 以小徽章/次级标签形式出现在品牌区旁、账户区或页面标题，不得出现在主品牌位 |

品牌锁定格式（展开态两行）：

```
SinoFUT
AI Commerce OS
```

## 3. 色彩系统

采用中性底色 + 单一 AI 强调色的克制配色，避免多彩数据可视化风格渗入界面底色。以下为 token 草案（浅色/深色两套），具体数值在 Phase 5 系统框架阶段落地为 CSS 变量：

| Token | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `--surface-base` | 页面底色 | `#FAFAF9` | `#0B0C0E` |
| `--surface-raised` | 卡片/画布底色 | `#FFFFFF` | `#16171A` |
| `--surface-sunken` | 输入框/次级容器 | `#F3F3F1` | `#1F2023` |
| `--text-primary` | 主文字 | `#141414` | `#F2F2F0` |
| `--text-secondary` | 次级文字 | `#6B6B68` | `#9A9A97` |
| `--text-tertiary` | 三级/提示文字 | `#A3A39F` | `#6B6B68` |
| `--border-subtle` | 弱边框 | `#E7E7E4` | `#2A2B2E` |
| `--ai-accent` | SinoFUT / AI 强调色（唯一强调色） | `#5B5BD6` | `#8A8AF0` |
| `--signal-success` | 验证通过/正向信号 | `#1E8E5A` | `#4ADE95` |
| `--signal-warning` | 风险/待处理 | `#B5750B` | `#F2B84B` |
| `--signal-danger` | 阻断/失败 | `#C0362C` | `#F2685E` |
| `--glass-surface` | 悬浮层毛玻璃底色 | `rgba(255,255,255,0.72)` | `rgba(22,23,26,0.72)` |
| `--glass-border` | 悬浮层边框 | `rgba(20,20,20,0.08)` | `rgba(255,255,255,0.10)` |

**原则**：全局只有一个强调色（`--ai-accent`），代表"这是 AI 生成/建议/驱动的内容"，用于区分"人类确定的经营数据"与"AI 建议"，不用于装饰。

## 4. 字体与排版

| 层级 | 字号 | 字重 | 场景 |
|---|---|---|---|
| Display | 32–40px | 600 | 驾驶舱核心数字（如今日利润）、Marketplace 首屏 |
| Title | 20–24px | 600 | 页面标题、卡片主标题 |
| Body | 14–15px | 400–500 | 正文、列表项 |
| Caption | 12–13px | 400 | 次级说明、时间戳、标签 |

中文场景优先保证行高（≥1.6）与字间距舒展度，避免后台软件常见的紧凑表格字号（12px 及以下）作为默认正文尺寸。

## 5. 间距与栅格

- 基础间距单位 **8px**，卡片内边距默认不小于 **24px**（禁止 V1 中常见的 12px 高密度后台内边距）。
- 页面级留白：主内容区左右留白随视口宽度弹性放大，宽屏下内容区最大宽度约束，避免内容被拉伸到贴边铺满。
- 卡片式布局为默认容器，仅经营中心（Operator）的结构化数据允许使用表格作为主容器。

## 6. 组件哲学（按场景，而非统一组件库压制差异）

| 场景 | 主容器形态 | 说明 |
|---|---|---|
| SinoFUT 入口 | 悬浮胶囊 + 毛玻璃对话面板 | 默认折叠为极简输入条，不常驻大面板 |
| Founder 驾驶舱 | 六问卡片网格 | 卡片数量固定为六个一级问题，禁止无限堆叠 KPI 卡片 |
| Growth 机会雷达 | 信息流卡片 + 关系图 | 机会以"信号强度"排序而非表格 |
| Studio | 无限画布 + 浮动工具面板 | 画布是唯一主容器，面板悬浮于画布之上，不占用固定侧栏空间 |
| Operator | 队列列表 + 结构化表格 | 系统中唯一默认使用表格的场景，因经营数据要求精确可核对 |
| 能力中心 | 资产网格 + 编辑器 / 编排画布 | Agent/Prompt/Skill 用编辑器态，Workflow 用编排画布 |
| Marketplace / Cloud | 目录卡片 + 详情页 | 类比现代产品官网的商品/服务展示逻辑 |
| 系统管理 | 标准表单/设置列表 | 唯一允许"传统后台"观感的区域 |

## 7. 动效原则

- 动画克制：仅用于状态反馈（如 Approval 待处理的呼吸提示）与页面过渡，不做装饰性动画。
- 页面/画布切换使用平滑淡入淡出或位移过渡（150–250ms），拒绝生硬跳变，也拒绝超过 400ms 的拖沓过渡。
- 遵循 `prefers-reduced-motion`：任何持续性动画（呼吸、脉冲）在该偏好下必须关闭或降级为静态高亮。

## 8. 层级与信息密度分级

| 密度等级 | 允许场景 | 说明 |
|---|---|---|
| 低密度 | SinoFUT、驾驶舱、Marketplace | 大留白、卡片化、强调品质感 |
| 中密度 | Growth、Studio 工具面板、能力中心 | 兼顾创作效率与视觉克制 |
| 高密度（仅限） | Operator 核心表格、系统管理 | 允许表格与更紧凑排版，但仍需遵守最小 24px 卡片内边距与≥14px 正文字号 |

任何页面在选择密度等级前，必须先判断其在架构文档中的"主体归属"，不得以"数据多"为由默认升到高密度。

## 9. 无障碍与响应式基线

- 所有强调色与信号色需满足 WCAG AA 对比度（浅色/深色分别校验）。
- 悬浮胶囊、画布工具、驾驶舱卡片在移动端需有明确的降级形态（折叠/抽屉），不得直接隐藏关键操作。
- 深色模式与浅色模式为一等公民，同步设计，不作为浅色模式的"反色"简单处理。
