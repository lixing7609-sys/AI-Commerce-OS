# ADR-0007 Founder Master Edition Development Charter

## Status

Accepted. Supersedes [ADR-0002B Founder V4 Commerce Operating Architecture Freeze](ADR-0002B-founder-v4-architecture-freeze.md)
in full. Number chosen because ADR-0004 through ADR-0006 are reserved by ADR-0002B §Status for
AI Advertisement Platform, Operator Cloud, and Commercial Model respectively — this decision does
not claim any of those.

---

## Context

ADR-0002B froze an 18-module/5-section Founder navigation tree on 2026-07-24 and required any
structural change to go through a new unfreeze ADR first. Between that freeze and this decision,
the Founder console's navigation was restructured twice in code — commit `2798e74` ("rebuild
Founder IA and consolidate Operator Lab") moved to an 11-group/34-module IA, and commit `9c6c82c`
("rebuild Founder navigation shell") added a further Core/Labs/Cloud visual zoning layer — without
either commit producing the unfreeze ADR that ADR-0002B's own rules required. The frozen document
and the running code diverged silently.

Separately, the product direction changed: Founder is no longer being developed as one edition
among several equally-weighted editions (Founder/Operator/Studio/Cloud per
[ADR-0002 Edition Boundary](ADR-0002-edition-boundary.md)). It is now the single permanent master
product — **AI Commerce OS Founder (Master Edition)** — from which Operator, Studio, Cloud, and
future industry editions are meant to be generated by permission and navigation pruning, not built
as independent codebases. This is a materially different architecture than either ADR-0002B or the
current code reflects, so a fresh, explicit decision record is required rather than a further
undocumented drift.

---

## Decision

1. **Adopt the Founder Master Edition Charter** as the sole navigation and architecture authority
   for `frontend/src/console/`, recorded in full at
   [`docs/architecture/Founder_Master_Edition_Development_Charter.md`](../architecture/Founder_Master_Edition_Development_Charter.md).
   Summarized: exactly 5 top-level navigation groups — Founder Workspace, AI Capability Center,
   Operator Lab, Studio Lab, Cloud Center — each with a fixed second-level item list as detailed in
   the charter.
2. **Supersede ADR-0002B and its companion freeze document**
   (`docs/01-reference-architecture/founder-v4-architecture-freeze.md`) in full. Both are marked
   `Superseded` with a banner pointing here and are retained for historical reference only — not
   deleted.
3. **Reframe standalone editions as compatibility shells, not independent products.** The
   hand-built `frontend/src/operator-preview/`, `frontend/src/studio/`, and `frontend/src/cloud/`
   entry apps are not deleted in this round, but are documented as temporary compatibility shells
   that consume the same shared navigation/registry/page definitions as Founder's embedded
   Operator Lab and Studio Lab. No new parallel implementation may be built for them; over time
   their remaining independent code should be migrated into Founder's shared modules.
4. **Establish the same unfreeze mechanism ADR-0002B used**: any structural change to the 5-group
   tree or its fixed second-level items requires a new ADR before implementation.

---

## Consequences

Positive:
- Restores a single authoritative, versioned navigation record after two undocumented drifts.
- Aligns the architecture record with the actual product direction (one master codebase, editions
  generated from it) instead of the now-obsolete equal-editions model.
- Every previously existing module/page/capability is explicitly accounted for in the charter's
  migration maps — nothing is silently dropped in this transition.

Negative:
- A second unfreeze step now exists in the repository's history (ADR-0002B unfroze nothing before
  drifting; this ADR is itself proof that a freeze without enforcement doesn't hold) — future
  changes to the 5-group tree must go through a new ADR, and that discipline must actually be
  followed this time.

---

## Rules Introduced

1. No structural change to the 5-group Founder navigation tree recorded in the
   [Founder Master Edition Development Charter](../architecture/Founder_Master_Edition_Development_Charter.md)
   may be made without a new ADR.
2. No new standalone edition app (a hand-built entry point independent of Founder's shared
   modules) may be created. Operator, Studio, Cloud, and future industry editions are generated
   from Founder by permission/navigation pruning.
3. Any capability, module, or page retired from a nav tree during this transition must be either
   absorbed into a new home, kept as a hidden resolvable deep link, or explicitly marked obsolete
   with a reason in the charter's migration maps — never silently dropped.
